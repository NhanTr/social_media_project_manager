# S3 Flutter Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or dispatching-parallel-agents for the two isolated domains. Track steps below.

**Goal:** Hoàn thành phần Flutter S3-02/S3-04 với demo repository, sẵn sàng thay adapter khi backend xong.
**Architecture:** Chat và notification độc lập, root tích hợp shell/session/router. Repository là boundary backend; demo state và queue scope theo account.
**Tech Stack:** Flutter, Dart, ChangeNotifier, PostLocalStore hiện có; không dependency mới.
**Spec:** `docs/superpowers/specs/2026-11-06-s3-flutter-design.md`

## Global Constraints

- Không sửa backend runtime; API contract hiện có là boundary cho adapter sau này.
- Không gọi fake data là dữ liệu backend; demo chỉ bật ở dev và có nhãn.
- Giữ auth, feed, composer, friends/profile và thay đổi người dùng.
- Queue persist trước network; key ổn định; session/account không được lẫn dữ liệu.
- READ phụ thuộc route visible + foreground + tin thực xem.
- Unknown/deleted/unauthorized target có fallback an toàn.

## Review Focus

- Race giữa queue persist, event ACK và reconnect không làm mất/trùng tin.
- Dispose/account switch chặn late network/event/write tác động session mới.
- READ không vượt visible watermark khi scroll lịch sử hoặc tab bị che.
- read-all/count refresh không xóa unread của arrival đồng thời.
- Cold-start/foreground payload sai hoặc account cũ không mở tài nguyên sai.
