# Sprint S2-02 / S2-03 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans with test-driven-development; independent backend, composer and feed domains may be delegated using dispatching-parallel-agents, with disjoint file ownership and final integration review.

**Goal:** Deliver resilient photo publishing and a real friends feed, then PR and Trello acceptance evidence.
**Architecture:** Flutter controllers use a shared typed PostsApi over the authenticated ApiClient. Inject photo, upload and storage adapters; persist account-scoped data. Extend post-service only for finalized-upload binding and idempotent creation.
**Tech Stack:** Flutter/Dart, image_picker, image, gal, Dio, path_provider; Spring/JPA/PostgreSQL/MinIO.
**Spec:** docs/superpowers/specs/2026-10-25-sprint-s2-02-03-design.md (approved by user 25 October 2026).

## Global Constraints

- Android/iOS acceptance; web must compile with unsupported-native-operation feedback.
- Maximum image edge 2048px, encoded JPEG below 5 MiB; caption maximum 2000 characters.
- Account-scoped durable drafts/cache; immutable publication UUID; real byte progress and abort; no duplicate post on ambiguous retry.
- Preserve existing V1–V4 migrations on dev; integrate media lifecycle as V5 and reliability schema as V6.
- Never mark platform checks passed without device evidence. Trello Review & QA requires PR; Done requires merge, green CI and acceptance.

## Review Focus

- Process termination between server commit and response: reuse publication UUID and frozen payload.
- Logout/filter changes during asynchronous reads: discard outdated responses and isolate files by account.
- Permission revoked or post blocked between viewing and saving: revalidate before native save.
- Refresh interleaved with load-more: generation check and unique IDs prevent obsolete append.
- Backend retries under concurrency: transaction/database guarantee, single notification fan-out.

## Shared interfaces (root owns)

`core/models/post_models.dart`: PostModel.fromJson(Map<String,dynamic>), toJson(), fields int id,userId; String mediaUrl,mediaType,status,authorName; String? caption,thumbnailUrl; DateTime createdAt. PostPage(items: List<PostModel>, nextCursor: String?, hasNext: bool). MediaUploadSession(uploadId:int,presignedUrl:String). UploadedMedia.fromJson/toJson; fields mediaUrl:String,mediaType:String,fileSizeBytes:int, mediaWidth:int?,mediaHeight:int?,durationSeconds:int?. PostApiException(statusCode:int,code:String?,message:String), toString message.

`core/network/posts_api.dart`: PostsApi(ApiClient api); Future<PostPage> feed({int? friendId,String? cursor,int limit=20}); Future<PostModel> detail(int id); Future<MediaUploadSession> createUpload(int bytes); Future<UploadedMedia> finalizeUpload(int uploadId); Future<PostModel> publish({required String clientRequestId,required int uploadId,required UploadedMedia media,required String caption,required String filterApplied}); Future<List<FriendSummary>> friends().

`core/storage/post_local_store.dart`: PostLocalStore({required int accountId}); Future<Map<String,dynamic>?> read(String key); Future<void> write(String key,Map<String,dynamic> value); Future<void> remove(String key); Future<void> clear(). Native files use atomic replace and serialized operations; web uses preferences. Both keys and paths are scoped by account. Stores JSON, so bytes are base64 at caller boundary.

Root alone changes pubspec, platform configuration, AppShell, auth/friends integration and shared files. Other owners must not edit them. Agents may run tests but do not commit shared tree changes; root commits coherent ranges.
